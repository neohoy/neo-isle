# 方寸之境 · 自成一格

用户要的东西预设里没有时走这一层：别的容器形状（瓶子、灯泡、玻璃房）、别的质感（低多边形、水墨、像素）、别的界面、别的后期，或者他就是想要一套属于自己的微缩世界风格，以后每一境都用它。

做法是把引擎复制一份到用户的目录里改。技能自带的 `core/` 不动，别的用户和以后的更新不受影响。

## 一、什么时候该走这一层

先确认前两层解决不了：

| 用户说的 | 该走哪层 |
|---|---|
| “换成沙漠”“把鹿换成骆驼”“加一座桥” | 第一层：改 `world.js` |
| “装进玻璃球”“放在桌上”“光再强一点”“系列名叫《掌中山河》” | 第二层：改 `meta.look` / `meta.title` |
| “某一境里要下雨 / 要极光 / 要一条龙” | 第一层：在 `world.js` 里用 `THREE` 做 |
| “容器要一只玻璃瓶”“整体要低多边形”“界面换成英文”“不要移轴”“昼夜改成四季” | 这一层 |

只为某一境加一样东西，不要动引擎。要改的是“以后每一境都这样”的东西，才动。

## 二、怎么做

1. **定范围。** 问清楚这套风格是只给这一境用，还是给整个系列用。
   - 整个系列：复制到 `<系列目录>/_core/`。
   - 只这一境：复制到 `P/_core/`。

   ```bash
   cp -R $SKILL/core <系列目录>/_core
   ```

   `build.py` 找引擎的顺序是 `P/_core/` → `<系列目录>/_core/` → 技能自带的 `core/`，找到哪个用哪个，并在构建时提示“使用自己的引擎”。

2. **写一页 `<系列目录>/_core/风格.md`。** 先写再改代码。写清楚：这套风格叫什么；和方寸之境比，换掉了什么、保留了什么；容器、背景、质感、镜头、界面各是什么；易错点。以后做这个系列的每一境都先读它，它的地位等同于 `references/风格规范.md`。

3. **改 `_core/fangcun.js` 和 `_core/template.html`。** 引擎的结构见下一节。把 `_core/VERSION` 改成自己的版本号（比如 `山河-1.0`）。

4. **拿示范境验证。** 把 `$SKILL/examples/01-雪山河谷/world.js` 复制到一个临时工程里，用新引擎构建，四个时辰出图。示范境在新引擎下还成立，才说明没有改坏公共部分。然后再做用户自己的境。

5. **登记。** 在 `系列境单.md` 顶上加一行：这个系列用的是自己的引擎，风格说明在 `_core/风格.md`。

## 三、引擎里什么在哪

`core/fangcun.js` 是一个函数 `startFangcun(WORLD)`，从上到下：

| 段落 | 内容 | 常见的改法 |
|---|---|---|
| 外观预设 | `LOOKS`、`look`、容器的几何函数（`ceilingY`、`inFoot`、`rowR`、`insideExpr`） | 加一种容器：在 `LOOKS.container` 里加名字，并让这四个函数认识它 |
| 渲染器、相机、灯 | 视角 20°、取景距离、主光阴影 | 换视角、换默认机位 |
| 造境工具 `F` | `terrain`、`ground`、`water`、`kit` 等 | 换质感多半改这里的材质（粗糙度、平涂、描边） |
| `WORLD.build(F)` | 调用世界文件 | 不动 |
| 收尾 | 雾、光柱、尘埃、玻璃、背景、后期 | 换玻璃着色器、换背景、去掉移轴或辉光 |
| 昼夜 | 十个时辰的关键帧 `KF`、太阳和月亮的轨迹 | 换整套天色、改成别的时间逻辑 |
| 界面与主循环 | 时辰滑杆、按钮、开场推镜 | 换文案、加按钮 |

`core/template.html` 是页面壳：标题、时钟、底部面板的结构和样式。换界面语言、字体、布局改它。

加一种新容器要过的几关（钟罩和球就是这么加的，可以照着找）：

1. 地块的边界和高度上限（`inFoot`、`ceilingY`，以及 `F.terrain` 里压低地形的那几行）。
2. 地表网格和剖面（`F.ground` 里圆形地块那一支）。
3. 海面和水体剖面（`F.water` 里）。
4. 玻璃的几何体和着色器（`containerGeo`、`roundVS` / `roundFS`）。
5. 着色器里的“在不在容器里”（`insideExpr`），雾的边界（`footClamp`），尘埃和星芒的取点。
6. 取景距离（`fitDistance`），桌面背景下的底座。

## 四、和技能更新的关系

`_core/` 是一份独立的副本，技能的引擎以后更新了，它不会跟着变。想跟上：对比 `$SKILL/core/` 和 `_core/` 的差异，把需要的改动手动并过去，再用示范境验证一遍。所以 `_core/风格.md` 里要记一句“从技能引擎的哪个版本复制的”。

已经发布的各境是自带引擎的单文件，引擎怎么改都不影响它们。
